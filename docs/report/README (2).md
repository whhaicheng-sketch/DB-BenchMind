# Report 文档总览

## 1. 我对当前需求的理解

当前要优化的不是一个单纯“更好看”的 Report 页面，而是一套围绕 **性能判断** 与 **AI 瓶颈分析** 的完整报告方案。

本轮设计的核心目标有两个：

1. **给人类看的 Report 必须高度聚焦**
   - 打开后应在 30 秒内看懂当前压测结果是否健康。
   - 能快速看到关键指标、瓶颈倾向、对比结论和下一步建议。
   - 不要被大量原始数据、长日志、细碎表格淹没。

2. **给 AI 的分析数据必须结构化且可控**
   - AI 输入数据不默认展示给用户。
   - 页面下方提供“详细数据”入口，默认收起，可看可不看。
   - AI 数据包必须压缩到 **1MB 以内**。
   - 长时间压测产生的大量数据不能无上限保留到 AI 包内，必须做采样、截断、降采样和异常窗口保留。

## 2. 设计原则

- **展示层与分析层分离**：人类看摘要，AI 看结构化证据包。
- **Markdown 作为主导出格式**：优先保证可读性、归档性和可扩展性。
- **结构化数据单独保存**：AI 分析依赖 JSON/压缩包，不依赖 Markdown 自由文本解析。
- **统一不同 benchmark 输出**：sysbench、Swingbench、HammerDB 最终归一到一套 Report Schema。
- **对超长压测做体积控制**：采用“前 / 中 / 后 + 异常窗口 + 时间序列降采样”的方式保留证据。
- **默认先看结论，再看证据**：不把原始数据直接堆到主界面。
