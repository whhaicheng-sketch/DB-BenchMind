# Report 实施计划

## 1. 实施目标

本计划用于把 Report 从“结果堆叠”推进到“快速判断 + AI 分析”的可交付形态。

## 2. 分阶段计划

## Phase 1：需求定稿与结构对齐

### 目标
- 固化设计边界
- 明确人类展示层与 AI 分析层的职责
- 明确 1MB 控制策略

### 输出
- requirements.md
- design.md
- spec.md
- plan.md
- tasks.md

### 验收
- 团队对文档结构与目标无歧义

## Phase 2：数据模型与采样策略落地

### 目标
- 定义统一 Report Schema
- 定义 AI Bundle Schema
- 定义前/中/后 + 异常窗口策略
- 定义时间序列降采样策略

### 输出
- 领域模型调整方案
- bundle 生成器接口定义
- 采样与压缩策略实现方案

### 验收
- 能在不依赖 UI 的情况下生成规范化 bundle

## Phase 3：Human Report 模板实现

### 目标
- 基于 Markdown 实现人类展示层模板
- 报告结构固定
- 指标、对比、资源摘要、结论可自动填充

### 输出
- Markdown 模板
- 导出示例
- 模板字段映射表

### 验收
- 打开报告 30 秒内可完成基本判断

## Phase 4：详细数据折叠展示

### 目标
- 在页面中加入详细数据入口
- 默认收起 AI 数据区
- 展示包大小、采样策略、窗口摘要和样本预览

### 输出
- 交互设计稿或前端实现方案
- 展示字段清单

### 验收
- 不展开详细数据也不影响用户阅读主报告

## Phase 5：对比与瓶颈判断接入

### 目标
- 接入 previous / baseline 对比
- 接入规则引擎版瓶颈判断
- 预留 AI 深度分析输出槽位

### 输出
- 对比数据生成逻辑
- 瓶颈判断规则初版
- 结论与建议生成策略

### 验收
- 报告能自动给出主瓶颈方向和建议

## 3. 风险与应对

### 风险 R1
长时压测数据体积过大，AI 包容易超限。

**应对**：
优先做降采样与异常窗口优先保留策略。

### 风险 R2
不同 benchmark 字段差异大，统一展示困难。

**应对**：
先抽象统一 schema，再映射 tool_specific 扩展字段。

### 风险 R3
AI 结论不稳定。

**应对**：
先以规则引擎输出初判，AI 负责补充解释和建议。

## 4. 推荐推进顺序

推荐严格按以下顺序推进：

1. 文档定稿
2. Schema 定稿
3. Bundle 生成能力
4. Markdown 模板实现
5. 页面详细数据折叠区
6. 对比与瓶颈判断
7. AI 深度分析接入

## 5. 里程碑

### M1：文档完成
- 需求、设计、spec、plan、tasks 全部完成

### M2：数据产物可生成
- report.md
- report_bundle.json.zst

### M3：页面展示可用
- Human Report 可看
- Detailed Data 可展开

### M4：分析结论可用
- 支持瓶颈判断与对比
