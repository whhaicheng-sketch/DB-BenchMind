## 背景

### 问题陈述

当前 DB-BenchMind 使用 Fyne GUI 框架，存在以下问题：

1. **图表能力有限**：Fyne 原生图表组件简陋，难以实现美观的实时监控图表
2. **扩展性差**：添加新图表或复杂 UI 需要大量底层绘制代码
3. **视觉效果**：无法达到类似 SwingBench 的专业监控界面效果

### 解决方案

采用 Wails 框架重构 UI 层：

- **后端**：继续使用 Go，保持现有业务逻辑
- **前端**：使用 Vue 3 + ECharts，实现专业级监控图表
- **集成**：通过 Wails 的 Go-JS 绑定实现数据通信

## 用户场景

### UC1：Benchmark 执行与监控

**角色**：DBA / 性能测试工程师

**前置条件**：
- 已配置数据库连接
- 已选择 Benchmark 模板

**主流程**：
1. 用户选择一个已配置的数据库连接
2. 用户选择一个 Benchmark 模板（如 OLTP Read-Write）
3. 用户设置参数（线程数、持续时间、Warmup 时间）
4. 用户点击 **Run** 按钮开始执行
5. 系统在**右侧图表面板**实时显示 TPM/TPS 图表
6. 系统在**左侧日志区域**实时显示 Benchmark 输出
7. 用户观察图表，检查是否存在锯齿波动
8. Benchmark 完成后，用户查看最终结果

**后置条件**：
- Benchmark 结果已保存到历史记录
- 图表显示最终状态

### UC2：系统资源监控

**角色**：DBA / 性能测试工程师

**前置条件**：
- Wails 应用已启动

**主流程**：
1. 系统自动开始采集本机 CPU/Disk IO/Disk Space
2. 系统在**右侧图表面板**实时显示系统指标图表
3. 用户观察系统资源使用情况
4. 用户启动 Benchmark，系统同时显示 TPM/TPS 和系统指标
5. 用户分析系统资源与 Benchmark 性能的关系

**后置条件**：
- 系统指标持续采集和显示

### UC3：波动分析与告警

**角色**：DBA / 性能测试工程师

**前置条件**：
- Benchmark 正在运行
- 已有足够的数据点（至少 30 秒）

**主流程**：
1. 系统自动计算 TPM/TPS 的变异系数（CV）
2. 系统根据 CV 值显示颜色告警（绿/黄/红）
3. 用户观察到红色告警，判断存在明显锯齿
4. 用户分析可能的原因（锁竞争、IO 瓶颈等）

**后置条件**：
- 波动分析结果已记录

| FR5.3 | TPM 迷你折线图（显示最近 60 秒趋势） | P0 | ✅ |
| FR5.4 | TPS 迷你折线图（显示最近 60 秒趋势） | P0 | ✅ |
| FR5.5 | 显示当前值、平均值、最大值 | P1 | ✅ |
| FR5.6 | Benchmark 未运行时显示 N/A 或 0 | P0 | ✅ |

**数据约定**：

| 场景 | TPM/TPS 显示 | 说明 |
|------|-------------|------|
| 程序启动，未运行 Benchmark | N/A 或 0 | **空态展示**：柱状图/折线图区域显示占位状态 |
| Benchmark 运行中 | 实时数值 | 每秒更新 |
| Benchmark 结束后 | 保留最后值或 N/A | 用户可选择清空 |
| Warmup 阶段 | N/A（不更新图表） | 等待 Warmup 结束 |

**空态展示定义**（重要）：
- 当 `benchmark_running = false` 时，TPM/TPS 图表应显示占位状态（如灰色横线、"N/A"文字、或空白）
- 空态时折线图区域无数据点或显示静态占位图形
- 空态不产生告警颜色变化（维持默认色或灰色）

## UI 设计

### 整体布局原则

**核心原则**：
1. **左右分栏布局**
2. **左侧为控制面板**（300px 固定宽度）
3. **右侧为图表面板**（自适应宽度，**主要展示区**）
4. **右侧是用户的主要视觉焦点**

## 附录

### 术语表

| 术语 | 定义 |
|------|------|
| TPM | Transactions Per Minute，每分钟事务数 |
| TPS | Transactions Per Second，每秒事务数 |
| CV | Coefficient of Variation，变异系数 = 标准差/平均值 |
| 锯齿 | 指标在短时间内频繁上下波动的现象 |
| Sparkline | 迷你折线图，用于显示趋势 |
| MVP | Minimum Viable Product，最小可行产品 |
