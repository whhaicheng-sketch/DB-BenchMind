# DB-BenchMind Wails 迁移规格文档

> 从 Fyne GUI 迁移到 Wails + Vue 3 + ECharts 的技术规格文档

---

## 目录说明

本目录是 DB-BenchMind **Wails 版本**的唯一规格来源，包含完整的需求、方案和任务定义。

### 适用范围

- **当前阶段**：Wails 版本的开发与实现
- **目标用户**：参与 Wails 版本开发的工程师
- **边界**：仅覆盖 Wails 版本，现有 Fyne 版本不在本规格范围内

### 当前阶段边界

| 在范围内 | 不在范围内 |
|----------|------------|
| Wails + Vue 3 + ECharts 前端开发 | 修改或删除现有 Fyne 代码 |
| 本机系统监控（CPU/Disk IO/Disk Space） | 远程数据库服务器监控 |
| TPM/TPS 实时图表 | 复杂告警中心 |
| 横向柱状图 + 趋势折线图 | 历史数据持久化与回放 |
| 并行开发 Wails 版本 | 直接替换 Fyne 版本 |

4. `README.md` 仅做说明，不作为需求变更依据

## Spec Coding 使用指南

### 实现阶段如何使用文档

```
┌─────────────────────────────────────────────────────────────────┐
│                     Spec Coding 工作流                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. 查看 tasks.md，找到下一个 Todo 状态的任务                     │
│                    ↓                                             │
│  2. 查看 requirements.md，确认该任务对应的需求定义                │
│                    ↓                                             │
│  3. 查看 plan.md，确认技术方案和架构边界                          │
│                    ↓                                             │
│  4. 实现代码（遵守 CLAUDE.md 编码规范）                          │
│                    ↓                                             │
│  5. 更新 tasks.md 任务状态为 Done                                │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 实现阶段必须遵守的规则

1. **必须以 `requirements.md` 为需求事实来源**
2. **必须以 `plan.md` 为实现路径依据**
3. **必须以 `tasks.md` 为任务范围依据**
4. **每次只执行明确指定的任务编号**
5. **不得擅自扩大范围**
6. **不得提前实现 backlog 内容**
7. **不得删除、破坏或替换现有 Fyne 代码**
8. **完成实现后必须同步更新 `tasks.md` 中对应任务状态**
9. **如发现文档与现状不一致，先按文档执行，并在结果中指出差异**

## 关键决策

### 迁移策略：并行开发

- ✅ **保留现有 Fyne 版本**，不做删除或修改
- ✅ 新建 Wails 版本入口，独立目录结构
- ✅ 待 Wails 版本达到可用标准后，再评估切换
- ❌ 当前阶段不得删除 Fyne 版本

**为什么采用并行开发？**
- 风险控制：避免迁移过程中影响现有功能
- 可回退：Fyne 版本始终可用作备份方案
- 渐进式迁移：可以逐步验证 Wails 版本的稳定性

### 监控范围：仅本机

- ✅ **当前阶段**：仅监控运行 DB-BenchMind 的本机
- ❌ **不在当前范围**：远程数据库服务器监控（预留扩展能力）

**为什么当前阶段不做远程采集？**
- 复杂度高：需要 SSH/Agent/WMI 等多种远程协议
- 安全性：涉及远程凭证管理
- MVP 原则：先保证本机监控稳定，再扩展远程

### 图表方案：横向柱状图 + 趋势折线图

- ✅ 使用 ECharts 实现图表
- ✅ 横向柱状图显示当前值
- ✅ 迷你折线图显示最近 60 秒趋势
- ✅ 支持波动分析和颜色告警（绿/黄/红）
